    Automated sending

    When configured, the templates below go out automatically on a schedule (check-in requests, stay reminders, feedback requests, and booking confirmations) instead of needing a manual click from Bookings.     Send a test message

    Sends one real Interakt message with sample data (a made-up guest, dates, and links — never a real stay) to any phone number, using whichever scenario's template name is saved below. Useful to confirm a template + API key actually work without waiting for a real stay to fall into the right date window.

    Delivery status webhook

    Interakt only says a message was accepted; whether it was actually delivered, read or failed comes later through this webhook. Paste the URL into Interakt → Settings → Developer Settings → Webhook, and tick the message API events (sent, delivered, read, failed). Bookings then shows Delivered ✓✓ / Read ✓✓ / Not delivered next to each send, and a failed send alerts Telegram with WhatsApp's reason. Keep this URL private — the key in it is what lets Interakt post here.

    Telegram notify setup

    One-time setup on Render: message @BotFather on Telegram, send /newbot, and set the token it gives you as TELEGRAM_BOT_TOKEN (a Render environment variable — not set from here). Each person who wants alerts then sends "hi" to the new bot from their own Telegram account, uses the button below to find their chat ID, and an admin enters it against their name in Settings → User Access — along with which of the 12 alert types they want to receive.

    WhatsApp templates

    Wording for the WhatsApp messages the site and dashboard pre-fill. Use {{token}} placeholders — a line containing a token with no value for that message is left out automatically, so a field can be made optional just by giving it its own line.

    {{name}} {{phone}} {{email}} {{checkin}} {{checkout}} {{nightsLabel}} {{guests}} {{occasion}} {{message}} {{quoteNo}}

    {{guest}} {{checkin}} {{checkout}} {{checkinLink}}

    The template's body must use placeholders 1 through 4, in this exact order: guest, check-in date, check-out date, check-in link.

    {{guest}} {{checkin}} {{checkout}} {{portalLink}}

    The template's body must use placeholders 1 through 4, in this exact order: guest, check-in date, check-out date, portal link.

    {{guest}} {{feedbackLink}}

    The template's body must use placeholders 1 and 2, in this exact order: guest, feedback link.

    {{quoteLink}}

    The template's body must use a single placeholder 1: the link to the guest's quote-review page.

    {{guest}} {{checkin}} {{checkout}} {{guests}} {{walletLink}}

    The template's body must use placeholders 1 through 5, in this exact order: guest, check-in date, check-out date, guest count, Apple Wallet link.

    Where bookings, cash, inventory and settings are kept — moving from GitHub to the Supabase database.     Photos — receipts, guest ID photos, signatures and checklist photos move from the public website repository into Supabase's private storage. Links in the data are updated; pages keep showing them. Preview counts what would move and tests the private storage without changing anything.

    Villas

    Other villas on RYST Harbour. Each villa has its own bookings, cash, inventory, settings and staff — its admin signs in with the email below (Google or Telegram) and sees only that villa. WhatsApp, online payments and calendar sync stay connected to this villa only for now.

    The villa ID can't be changed later: lowercase letters, numbers and dashes. The admin email must not already be a user here.
